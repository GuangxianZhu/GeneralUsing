# 调查工作区说明

这个工作区用来做技术调查:回答控制系统功能的问题、调查故障、比较版本差异。
使用者是功能工程师,负责下位层,读代码、做审查,不写产品代码。

## 开工前

- 先读 `.github/source-map.md`,各信息源的位置和访问方法都在里面。
- 地图里状态是「未确认」的来源,使用前先做一次最小的读取测试。
- 问题没有说明版本、客户分支或机台时,先问清楚再查。

## 信息源使用规则

- 所有来源只读。
  - 数据库只执行 SELECT。
  - VSS 只用 Get、Dir、History,不 Checkout。
  - SVN 和 Git 只做取得、查看历史、比较,不提交、不推送。
- 取回的数据先存到 `work/<任务名>/`,再从文件里检索。大量原始数据不直接贴进对话。
- 账号密码从环境变量读取(变量名见地图),不写进脚本、报告和对话。
- 时间分界:2022 年以前的要求和故障在老数据库,之后的在 Microsoft 365。跨分界的问题两边都查。
- 版本分界:旧版代码在 SVN,新版代码在 Azure Repos。两套代码独立,下位层有很多共通函数。
- 某个来源连不上时,写明是哪个来源、什么错误,用其余来源继续,并在报告里注明缺了什么。

## 报告

- 结论放最前面,一两句话。
- 每条依据带出处:文件路径和行号、表名和主键、文档名和页码、VSS 路径和版本号。
- 「查到的事实」和「推断」分开写,推断注明依据的是哪几条事实。
- 来源之间有矛盾时两边都列出。
- 没查到的内容写「没查到」,并列出查过的地方。
- 报告用中文,信号名、参数名、日文术语保持原文。
- 保存为 `work/<任务名>/报告.md`。
